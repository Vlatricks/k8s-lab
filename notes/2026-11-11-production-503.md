# 503 на production после первого деплоя

**Симптом:** `curl http://production.skillbox.local` возвращал `503 Service Temporarily Unavailable` от nginx, а staging отвечал нормально.

**Как искал причину:**
- `kubectl get deploy,pods,svc,endpoints -n production`: Service есть, endpoints пустые, подов нет.
- `kubectl get deploy -A`: Deployment есть только в `staging`.

**Причина:** манифесты для production создавались командой `sed ... deployment.yaml service.yaml | kubectl apply -f -`. Два файла склеились в один поток без разделителя `---`, и второй затёр первый: создался только Service.

**Что ещё не сработало:** `kubectl apply -n production -f deployment.yaml` отказывается, если в манифесте прописан другой namespace.

**Решение:** применять файлы по одному, а потом перейти на Kustomize (`base` + `overlays`), чтобы не подменять namespace через `sed`.

**Вывод:** 503 от Ingress означает, что за Service нет готовых подов. Первым делом смотреть `endpoints`.
